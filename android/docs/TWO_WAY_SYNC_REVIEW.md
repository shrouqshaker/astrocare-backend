# مراجعة نسخة AstroCare 1.1-two-way

تم تنفيذ المزامنة البسيطة في الاتجاهين **داخل الموبايل فقط**، دون تعديل ملفات الباك اند أو نشر نسخة جديدة منه أو إضافة endpoints إليه. تاريخ المراجعة: 14 نوفمبر 2026.

## ما أصبح يعمل

زر **Settings → Sync now** وعامل WorkManager الدوري ينفذان رفع دفعة البيانات المعلقة، ثم تنزيل القياسات والأعراض والتنبيهات المحفوظة عبر مسارات التاريخ الموجودة. عدم وجود بيانات معلقة يلغي POST فقط، ولا يلغي التنزيل.

تُفحص الاستجابات الثلاث ثم تُدمج في Room داخل transaction واحدة. السجل الجديد يدخل بحالة synced ولا يُرفع مرة أخرى، والسجلات المحلية لا تُحذف بسبب غيابها من الرد. تكرار نفس ID والمحتوى لا يكرر السجل. اختلاف المحتوى لنفس ID يُعرض كتعارض مع الاحتفاظ بالبيانات المحلية.

Overview يعيد حساب الحالة والـ insights تلقائيًا عند وصول قياسات أو أعراض إلى Room، بجانب تحديث قائمة القراءات. Trends يتحدث من تدفق بيانات Room. إعادة التقييم هنا للعرض فقط ولا تنشئ تنبيهات تاريخية أو إشعارات جديدة من السجلات المنزلة.

**الحسابات تظل محلية.** هذه النسخة لا تستخدم `/overview` أو `/trends` لاستبدال نتائج الشاشات. الفائدة من الباك اند هي مزامنة السجلات الأصلية، لا التبديل بين محركي حساب مختلفين.

## إصلاحات السلامة التي راجعتها

إقرار التنبيه أثناء POST لا يضيع عند وصول رد أقدم؛ تحديث synced مشروط بأن قيمة الإقرار الحالية ما زالت هي التي أُرسلت. التنزيل لا يلغي إقرارًا محليًا معلقًا، والتنبيه المؤكد يمكنه تبني أول توقيت إقرار قبله السيرفر.

الردود ذات IDs غير مطلوبة أو متكررة، أو summary لا يطابق حالات العناصر، تُرفض قبل تطبيقها. هوية UUID في الرد يمكن أن تختلف في حالة الحروف دون إضاعة تحديث الصف المحلي، بينما النصوص العادية مثل note لا تُطبّع كأنها IDs.

المزامنة الدورية واليدوية تمران عبر mutex مشترك، وطلبات Sync now المتكررة تستخدم KEEP. تعطيل المزامنة يلغي العمل الدوري واليدوي. إذا تغير السيرفر أو هوية المستخدم أو API key أثناء GET، تُرفض استجابته قبل الدمج. واجهة حفظ Base URL تستخدم نفس التحقق المستخدم في عميل الشبكة.

نجاح الرفع مع فشل التنزيل لا يُعرض كنجاح كامل. Settings يعرض مرحلتي الرفع والتنزيل منفصلتين، وعدد المستلم والمضاف، والتعارضات وحدود التاريخ. التشخيصات محفوظة في DataStore مستقل، دون تخزين API key أو قيم القياسات فيه. لم تتغير نسخة مخطط Room، فلا يحتاج هذا التحديث إلى مسح قاعدة بيانات المستخدم.

أثناء Android Lint ظهرت مشكلة قديمة في إرسال التذكيرات: احتمال سحب إذن الإشعارات بين التحقق والإرسال. أضفت معالجة صريحة لـ SecurityException بدل إخفاء الفحص أو تجاهله.

```bash
ASTROCARE_LIVE_READ_ONLY=true ./gradlew --no-daemon assembleDebug testDebugUnitTest lintDebug
```

- **الاختبارات:** 213 اختبارًا، 0 failures، 0 errors، 0 skipped. تشمل اختبارات القواعد القديمة، HTTP/Retrofit، Room، WorkManager، سباقات الإقرار، تحديث ViewModels، Compose لحالة المزامنة، وأذونات التذكيرات.
- **Android Lint:** 0 errors و24 warnings. التحذيرات المتبقية تخص نسخ مكتبات/target SDK، موارد قديمة غير مستخدمة، واقتراحات KTX وتنظيف؛ لم أضف suppression أو baseline لإخفاء أخطاء.

## الحدود التي لم أخفها

هذه مزامنة للديمو، وليست بروتوكول إنتاج شاملًا. كل مسار تاريخ يعيد حتى 1000 سجل، ولا توجد pagination أو change cursor في النسخة الحالية للباك اند. الوصول إلى الحد يعرض تحذيرًا بأن اكتمال التنزيل غير مضمون، بدل إعلان نجاح كامل. طلبات التاريخ الثلاثة ليست snapshot متزامنة على السيرفر؛ أي تغييرات تحدث بينها تُلتقط في محاولة لاحقة.

لا تدعم النسخة تعديل/حذف القياسات أو نشر أحداث حذف أو عزل عدة حسابات في قاعدة محلية واحدة. الهوية الحالية في الواجهة ثابتة على الديمو؛ لا ينبغي استخدام تغيير هوية مخزنة يدويًا كميزة تبديل حسابات. عند اختلاف جسم سجل له نفس ID نحافظ على النسخة المحلية ونبلّغ بالتعارض، ولا ندعي أننا حللناه تلقائيًا.

لم أشغّل التطبيق على هاتف فعلي أو محاكي Android في هذه الجولة. التحقق التنفيذي كان عبر JVM/Robolectric وHTTP الفعلي للقراءة وفحوص APK. المفتاح التجريبي ومحتوى القواعد لا يجعلان التطبيق مناسبًا لبيانات صحية حقيقية أو استخدام طبي فعلي.

## تجربة النسخة

ثبّتي APK كتحديث فوق الـ APK السابق المرسل هنا، ثم افتحي **Settings → Sync now**. تابعي **Two-way sync**: يجب أن تظهر حالة الرفع والتنزيل منفصلة. بعد نجاح التنزيل، Overview وTrends يعرضان بيانات Room المدمجة ويستمران في العمل دون إنترنت.
